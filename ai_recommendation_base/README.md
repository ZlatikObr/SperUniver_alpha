# База AI-кейсов и инструментария для «Ревизора»

Эта папка нужна как рабочая база доказательств для будущей генерации рекомендаций по внедрению ИИ. Она собрана под проект «Ревизор»: AI-инструмент первичного бизнес-скрининга для консалтинговых агентств, где нужно быстро диагностировать бизнес, подобрать релевантные услуги и собрать КП.

## Файлы

- `ai_financial_cases.csv` - финансовая витрина: 62 кейса с деньгами, cost/revenue %, ROI или модельной оценкой для SMB.
- `ai_implementation_cases.csv` - 108 кейсов внедрения ИИ и автоматизации с количественным эффектом.
- `README.md` - правила использования базы, скоринг и шаблон рекомендации.

## Как устроены CSV

Разделитель - `;`, чтобы файл было удобно открывать в Excel/Sheets в русской локали.

### `ai_financial_cases.csv`

Это первый файл для финансовых рекомендаций и питча. В нем не смешиваются факты и расчеты:

- `case_type` - `real_public` для публичных кейсов, `synthetic_model` для модельных сценариев под «Ревизор».
- `financial_metric_type` - тип эффекта: `cost_savings`, `profit_improvement`, `revenue_percent`, `roi_and_cost_savings`, `modeled_savings` и т.д.
- `reported_financial_effect` - финансовый эффект человеческим языком.
- `reported_money_low`, `reported_money_high`, `currency` - денежный диапазон, если он раскрыт или смоделирован.
- `financial_percent_low`, `financial_percent_high` - процентный эффект, если источник дает cost/revenue/CPA/ROI.
- `annualization` - годовой, месячный, multi-year, per-process или модельный статус.
- `recommended_reuse` - как использовать кейс в рекомендации для клиента.
- `source_quality`, `confidence` - качество источника и надежность.

`synthetic_model` не является доказательством чужого результата. Это расчетная заготовка: в КП ее можно использовать только после подстановки клиентских чисел.

### `ai_implementation_cases.csv`

Это широкая база кейсов: часть строк финансовая, часть про часы, скорость, качество, adoption и технический эффект.

Ключевые поля:

- `company` - компания из кейса.
- `industry` - отрасль.
- `ai_area` - тип AI-сценария: support automation, document processing, Copilot productivity, route optimization и т.д.
- `use_case` - что именно внедряли.
- `quantitative_effect` - измеримый эффект: часы, деньги, проценты, снижение time-to-value, рост конверсии.
- `effect_status` - `actual`, `projected` или `potential`.
- `implementation_pattern` - архитектурный/организационный паттерн.
- `revizor_zone` - зона диагностики «Ревизора»: `finance`, `operations`, `marketing`, `team`, `strategy`.
- `how_to_reuse_in_recommendations` - как превращать кейс в аргумент для рекомендации.
- `source_url`, `source_type`, `confidence` - источник и надежность.

## Таксономия инструментов

Для «Ревизора» полезно группировать рекомендации не по названию вендора, а по типу внедрения:

1. **LLM/RAG knowledge assistant** - поиск по внутренним знаниям, методологиям, политикам, базе услуг.
2. **Document AI** - извлечение метрик из PDF, Excel, CSV, отчетов и договоров.
3. **Support/presales agent** - первичный диалог, квалификация запроса, FAQ, маршрутизация.
4. **Proposal generation** - КП, презентации, резюме аудита, коммерческие формулировки.
5. **AI analytics/forecasting** - спрос, выручка, churn, inventory, маркетинговая эффективность.
6. **Process mining/RPA/agentic automation** - поиск узких мест и автоматизация повторяемых процессов.
7. **AI coding/dev productivity** - ускорение разработки, тестов, ревью, инцидентов.
8. **Governance/evals/observability** - оценка качества, рисков, стоимости, latency, human-in-the-loop.

## Скоринг кейсов для рекомендаций

Для каждой потенциальной рекомендации выбираем 3-5 похожих кейсов из CSV и считаем приоритет.

Если рекомендация идет в питч, финансовую модель или КП, сначала брать `ai_financial_cases.csv`, затем добирать контекст из `ai_implementation_cases.csv`.

```text
priority_score =
  0.30 * business_impact
+ 0.25 * similarity_to_client_problem
+ 0.20 * implementation_feasibility
+ 0.15 * data_readiness
+ 0.10 * proof_strength
- 0.15 * risk_complexity
```

Оценка 0-5:

- `business_impact`: есть ли деньги, часы, конверсия, SLA, снижение риска.
- `similarity_to_client_problem`: похожа ли боль клиента на кейс.
- `implementation_feasibility`: можно ли сделать MVP за 2-8 недель.
- `data_readiness`: есть ли документы, CRM, звонки, FAQ, отчеты, логи.
- `proof_strength`: `high` для первичных источников и actual-эффекта.
- `risk_complexity`: PII, регуляторика, prompt injection, репутационный риск, зависимость от качества данных.

## Финансовая модель рекомендации

Для «Ревизора» нельзя механически переносить чужие миллионы на клиента. Денежный эффект считать через клиентскую базу:

```text
labor_savings =
  monthly_volume
* manual_minutes_per_item / 60
* loaded_hourly_cost
* automation_share

revenue_uplift =
  current_revenue_base
* conservative_uplift_percent
* gross_margin

payback_months =
  implementation_cost
/ monthly_net_benefit
```

Минимальные поля, которые нужно попросить у клиента для расчета:

- объем лидов, документов, обращений или заказов в месяц;
- ручное время на единицу;
- ставка/стоимость часа сотрудника с налогами и накладными;
- текущая конверсия, CPA, маржа или средний чек;
- стоимость внедрения и ежемесячная стоимость AI-инфраструктуры;
- доля задач, которую реально можно автоматизировать без риска.

Рекомендуемый тон в КП:

- публичные кейсы: «публичный бенчмарк показывает диапазон эффекта»;
- synthetic model: «модельная оценка для вашего процесса при указанных допущениях»;
- projected/potential: «целевой ориентир пилота, не гарантированный результат».

## Алгоритм генерации рекомендации

1. Из диагностики клиента определить главную боль: скорость КП, ручной документооборот, плохая конверсия, дорогой саппорт, хаос в данных, перегруз экспертов.
2. Сопоставить боль с `revizor_zone` и `ai_area`.
3. Для финансового обоснования отфильтровать `ai_financial_cases.csv`: сначала `case_type=real_public`, затем `confidence=high`.
4. Если похожих публичных кейсов мало, добавить `synthetic_model`, но явно пометить его как расчет.
5. Взять 3-5 кейсов с похожим паттерном и количественным эффектом.
6. Сформировать карточку рекомендации:

```text
Название: AI-помощник первичного пресейла
Боль: консультанты тратят 8-16 часов на квалификацию и КП.
Решение: LLM-опрос + RAG по базе услуг + генератор КП.
Пилот: 20-30 реальных лидов, 2 недели, human review всех КП.
Метрики: время до черновика КП, доля автозаполненных разделов, конверсия в встречу, стоимость обработки лида.
Бенчмарки: Klarna, Presidio, Salesforce, Wayfair.
Ожидаемый эффект: осторожно считать как диапазон, например 30-60% сокращения ручного времени на первом этапе, пока нет своих данных.
Риски: качество исходных данных, галлюцинации, коммерческая тайна, юридическая проверка обещаний ROI.
```

## Правила надежности

- Для питча лучше брать `confidence=high` и `effect_status=actual`.
- `projected` и `potential` использовать как ориентиры для целевых KPI, а не как доказанный эффект.
- Не переносить чужой ROI напрямую на клиента. Пересчитывать через его базовые числа: стоимость часа, объем лидов, конверсию, SLA, долю ручного труда.
- Если источник не первичный, в КП писать мягко: "публично сообщалось", "по данным кейса", "можно использовать как ориентир".
- Для AI-рекомендаций с документами всегда добавлять human review, логирование, проверку источников и запрет на хранение чувствительных данных без согласования.
- Любую строку `synthetic_model` подписывать как расчетный сценарий, а не как кейс реальной компании.
