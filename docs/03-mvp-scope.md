# MVP Scope — что именно делаем за 3 дня

## Главный пользовательский сценарий (E2E)

```
[1] Пользователь открывает веб-приложение
 ↓
[2] Проходит адаптивный опрос (10 вопросов: отрасль, размер, выручка, боли, цели)
 ↓
[3] Прикрепляет документ (PDF / CSV / Excel) — или нажимает «без документов»
     → с документом: AI парсит и извлекает ключевые метрики
     → без документа: AI обогащает профиль через поиск по открытым данным
 ↓
[4] AI формирует диагностику: оценка по 5 зонам + топ-3 риска
 ↓
[5] Система показывает витрину релевантных услуг (из каталога)
 ↓
[6] Пользователь выбирает услуги в корзину
 ↓
[7] Система генерирует КП (PDF) с выбранными услугами, ROI и следующими шагами
```

**Этот сценарий проходит от начала до конца на демо без ручной магии.**

---

## Что входит в MVP

### Frontend (Streamlit)
- Шаг 1: форма опроса (10 полей, адаптивная логика — часть вопросов зависит от ответов на предыдущие)
- Шаг 2: загрузка файла (PDF / CSV / Excel) + кнопка «без документов»
- Шаг 3: страница диагностики — оценка по 5 зонам + топ-3 риска
- Шаг 4: витрина услуг с чекбоксами (из `services_catalog.json`)
- Шаг 5: кнопка «Сгенерировать КП» → скачать PDF

### Backend / агент (FastAPI + Claude)
- **Опрос:** формирование структурированного профиля бизнеса из ответов
- **Парсинг документа:** pdfplumber (PDF) / pandas (CSV, Excel) → извлечение ключевых метрик
- **Fallback без документа:** поиск по открытым данным (Anthropic web tool или серп по отраслевым источникам)
- **Аудит AI:** Claude анализирует профиль → JSON с оценками по зонам (финансы, операции, маркетинг, команда, стратегия) + топ-3 риска
- **Подбор услуг:** фильтрация `services_catalog.json` по зонам риска и отрасли
- **Генерация КП:** markdown → PDF через weasyprint или md-to-pdf

### Данные
- `services_catalog.json` — 15–20 услуг с описанием, ROI, сроком, ценой (Алсу готовит)
- 5 синтетических бизнес-профилей для тестирования (разные отрасли)

### Тест-сценарии (минимум 5)
1. **Happy path с документом** — PDF финотчёта, полный пайплайн до КП.
2. **Happy path без документа** — только ответы на опрос, AI использует открытые данные.
3. **Edge case: нераспознанный документ** — JPG вместо PDF → graceful ошибка.
4. **Edge case: минимальный профиль** — клиент ответил на 4 из 10 вопросов → частичная диагностика с предупреждением.
5. **Негатив: prompt injection** — в поле «описание бизнеса» вставлен вредоносный промпт → система игнорирует и обрабатывает как текст.

## Что НЕ входит в MVP

- ❌ Авторизация, личный кабинет, история сессий.
- ❌ White-label кастомизация (логотип/цвета агентства).
- ❌ Генерация PPTX (только PDF в MVP).
- ❌ Реальный биллинг и оплата.
- ❌ CRM-интеграция (AmoCRM, Битрикс24).
- ❌ Мультиязычность (только русский).
- ❌ Реальная витрина конкретного агентства — используем синтетический каталог.

Эти пункты — **в roadmap**, не в питче «что сделано».

## Распределение работы по дням

| День | Фокус | Артефакт |
|---|---|---|
| 1 | Спецификация + каталог услуг + синтетические профили | Артефакт 1 |
| 2 | Прототип — опрос, парсинг, аудит-агент | Артефакт 2 |
| 3 | Прototип — витрина, корзина, КП-генерация, экономика, питч | Артефакты 2 + 3 + питч |

## Технологический стек

| Слой | Технология |
|---|---|
| UI | Streamlit |
| API | FastAPI (Python 3.11) |
| AI | Claude Sonnet 4.6 (Anthropic API) — основной агент |
| Парсинг документов | pdfplumber, pandas |
| Каталог услуг | JSON-файл |
| КП-генерация | weasyprint (markdown → PDF) |
| Поиск открытых данных | tool_use с web_search (встроен в Claude API) |
| Конфиги / промпты | YAML-файлы в `/prompts/` |
| Деплой демо | Streamlit Cloud / ngrok |
