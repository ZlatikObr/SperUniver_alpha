# MVP Scope — что именно делаем за 3 дня

## Главный пользовательский сценарий (E2E)

```
[1] Юзер открывает веб-приложение
 ↓
[2] Заполняет короткую форму о сети (формат, точки, выручка) — 6 полей
 ↓
[3] Загружает CSV/Excel со списаниями (или нажимает «использовать демо-датасет»)
 ↓
[4] Агент валидирует данные → показывает индикатор прогресса по шагам
 ↓
[5] Агент выполняет 4 шага (структурный анализ → бенчмаркинг → генерация инициатив → ROI)
 ↓
[6] Юзер видит дашборд + скачивает PDF-отчёт
```

**Этот сценарий должен пройти от начала до конца на демо без ручной магии.**

## Что входит в MVP

### Frontend (Streamlit или Next.js — выбираем по скорости)
- 1 страница с формой + загрузкой файла
- Прогресс-бар выполнения шагов агента
- Дашборд с 4 блоками: структура потерь, аномалии, 3 инициативы, ROI-таблица
- Кнопка «скачать PDF»

### Backend / агент
- Парсер CSV/Excel (валидация колонок, нормализация)
- Структурный анализ (pandas: топ-5 категорий, топ-5 точек, сезонность)
- RAG по БД из 10 кейсов (JSON-файл с эмбеддингами, поиск по cosine similarity)
- Промпт-цепочка на Claude Sonnet 4.6: 4 шага с явным контрактом ввода/вывода
- Генерация PDF (markdown → pdf через `md-to-pdf` или `weasyprint`)

### Данные (см. `05-data-strategy.md`)
- Синтетический датасет на 10 000 строк
- БД из 10 публичных кейсов (Auchan, Лента, ВкусВилл, Магнит, X5, и т.д.)

### Тесты (минимум 5)
1. Базовый сценарий — валидный CSV, 6 месяцев данных.
2. Грязные данные — пропуски в колонках, разные форматы дат.
3. Маленький датасет — 1 месяц, 1 точка (граничный случай).
4. Аномальный датасет — нулевые списания (агент должен сказать «нет данных для анализа»).
5. Негативный — CSV с не теми колонками (агент должен корректно отказать).

## Что НЕ входит в MVP (явно фиксируем)

- ❌ Интеграция с 1С через API.
- ❌ Реальные данные реальных сетей (только синтетика).
- ❌ Авторизация / личный кабинет.
- ❌ Биллинг / оплата.
- ❌ CV-модели для распознавания свежести (только текстовые рекомендации).
- ❌ Real-time мониторинг.

Эти пункты — **в roadmap для следующих шагов**, но не в питче «что сделано».

## Распределение работы по дням

| День | Фокус | Артефакт |
|---|---|---|
| 1 | Спецификация + БД кейсов + синтетика | Артефакт 1 |
| 2 | Прототип — каркас, агент, парсинг | Артефакт 2 |
| 3 | Прототип — UI, PDF, экономика, питч | Артефакты 2 + 3 + питч |

## Технологический стек (черновик)

- **Язык:** Python 3.11
- **UI:** Streamlit (быстрее) или Next.js (красивее)
- **AI:** Claude Sonnet 4.6 через Anthropic API
- **Анализ данных:** pandas, numpy
- **PDF:** weasyprint или md-to-pdf
- **Логирование:** простой JSONL-лог по шагам агента
- **Конфиги:** YAML (промпты, пороги, бенчмарки)
- **Деплой демо:** Streamlit Cloud / Vercel / локально с ngrok
