# Критерии оценки МФТИ — стратегия максимизации баллов

## Общая цель: 38–40 / 40 (сильный PDLC-MVP)

4 критерия, каждый по 10 баллов. Минимум для прохождения: 4 балла по каждому + 24 суммарно.

---

## Критерий 1. Артефакт 1 — PDLC-спецификация (цель: 10/10)

| Признак | Баллы | Наш план |
|---|---|---|
| Проблема сформулирована | +1 | 30–40% времени консультанта на пресейл, КП готовится 3–7 дней |
| ≥2 User Story с AC | +2 | US-1: диагностика бизнеса; US-2: генерация КП из витрины |
| DoD для AI-функции | +2 | Категоризированный DoD: 5 групп, 20+ конкретных критериев |
| AI Policy | +2 | Источники данных, границы анализа, поведение при недостатке данных, защита от injection |
| Ограничения и риски MVP | +1 | Явный список out-of-scope + топ-3 технических риска |
| Спец согласована с архитектурой | +2 | Trace-матрица US → компонент → технология |

**Чего избегаем:**
- ❌ User Stories как технические требования.
- ❌ Формальная AI Policy без конкретных примеров поведения.

---

## Критерий 2. Артефакт 2 — Прototип (цель: 10/10)

| Признак | Баллы | Наш план |
|---|---|---|
| Запускается без ручной магии | +2 | `streamlit run app.py` — одна команда |
| Основной сценарий E2E работает | +3 | Опрос → документ → аудит → витрина → корзина → КП |
| AI-компонент работает | +2 | Claude: адаптивный опрос + анализ профиля + подбор услуг + КП |
| Логирование шагов | +1 | JSONL-лог каждого шага агента |
| Промпты и конфиги версионированы | +1 | YAML в `/prompts/`, не хардкод |
| ≥5 тест-сценариев | +1 | См. `03-mvp-scope.md` |

**Критические минусы (избегаем!):**
- ❌ Прototип не запускается → −4 (дисквалификация).
- ❌ Команда не понимает, как работает AI-компонент → −3.

## Критерий 3. Артефакт 3 — Экономика и метрики (цель: 10/10)

| Признак | Баллы | Наш план |
|---|---|---|
| Cost-per-task | +2 | Токены × тариф Sonnet 4.6 + инфра; реальные цифры из логов |
| 2 сценария (base/optimistic) | +2 | Base: 20 аудитов/мес; Optimistic: 80 аудитов/мес + 5 агентств на подписке |
| Trade-offs (качество/скорость/цена) | +2 | Sonnet vs Haiku; с парсингом документа vs без |
| ROI с привязкой к продуктовым метрикам | +2 | LTV/CAC, конверсия опрос→КП, retention агентств |
| Ограничения и допущения | +2 | Явный раздел «что расчёт не учитывает» |

## Критерий 4. PDLC-целостность и питч (цель: 10/10)

| Признак | Баллы | Наш план |
|---|---|---|
| Питч по PDLC-логике | +2 | Проблема → требования → архитектура → реализация → тесты → экономика |
| Все три артефакта связаны | +3 | Сквозной кейс: агентство «Х» использует Ревизор, получает КП |
| Питч соответствует демо | +2 | Репетируем с реальным запуском |
| Реалистичные следующие шаги | +1 | White-label кастомизация → пилот с одним агентством → CRM-интеграция |
| Вклад каждого участника понятен | +2 | Каждый объясняет свой блок на Q&A |

---

## Контрольный чек-лист перед питчем

- [ ] Прототип запускается одной командой
- [ ] E2E сценарий (опрос → КП) проходит на демо
- [ ] Числа в питче = числа в Артефакте 3
- [ ] Каждый член команды объясняет свой блок
- [ ] Ограничения MVP явно названы в каждом артефакте
- [ ] Минимум одна репетиция с таймером
