## 1. Проблема и ценность

### 1.1. Описание проблемы

Розничные сети (20–200 магазинов) ежемесячно теряют 1–3% выручки на списания: порча, кража, ошибки учёта в 1С. Руководство узнаёт о структуре потерь с задержкой 2–4 недели — аналитик вручную обрабатывает выгрузку из 1С 3–5 рабочих дней. К моменту получения отчёта ситуация уже изменилась.

Триггер: ежемесячный аудит или внезапный рост потерь. Частота столкновения с проблемой: ежемесячно для каждой сети с нормальным процессом аудита.

### 1.2. Целевая аудитория

Директор по потерям (Loss Prevention Manager) / коммерческий директор / финансовый директор розничной сети с 20–200 магазинами. Использует продукт при ежемесячном аудите — загружает выгрузку из 1С, получает диагностику за 5 минут.

Порядок целевой аудитории: ~5 000–10 000 розничных сетей среднего размера в РФ.

### 1.3. Сегодняшняя альтернатива и её ограничения

Сейчас: ручная обработка выгрузки из 1С аналитиком (3–5 рабочих дней, 15 000–40 000 руб. стоимость рабочего времени) или привлечение внешних аудиторов (от 200 000 руб., 2–4 недели).

Ограничения: медленно, дорого, результат устаревает к моменту получения руководством.

### 1.4. Ценность нашего решения

Ревизор сокращает диагностику с 3–5 дней до 5 минут. Пользователь получает структуру потерь по категориям и магазинам + 3 приоритизированные инициативы с ROI.

Измеримая разница: **5 мин vs 3–5 дней**, **~50 руб./task vs 15 000–40 000 руб.** стоимости ручного анализа.

## 2. Пользовательские сценарии (User Stories)

### User Story 1

**Как** директор по потерям (Loss Prevention Manager) розничной сети  
**Я хочу** загрузить выгрузку о списаниях из 1С и получить диагностику структуры потерь по категориям и магазинам  
**Чтобы** понять, где именно возникают потери и что нужно исправить в первую очередь — без ожидания ручного отчёта аналитика

**Приоритет:** must · **Оценка трудоёмкости:** 16 часов

**Acceptance Criteria:**
- Система принимает CSV/Excel-файл в формате стандартной выгрузки из 1С без ручной предобработки
- Потери классифицированы по категориям (порча, кража, ошибки учёта, прочее) с суммами и долями в %
- Диагностика отображается в читаемом отчёте без технических терминов; время получения ≤5 минут

### User Story 2

**Как** директор по потерям розничной сети  
**Я хочу** получить 3 приоритизированные инициативы по сокращению потерь с расчётом ROI  
**Чтобы** предложить конкретный план действий руководству с обоснованием бизнес-эффекта, не привлекая внешних консультантов

**Приоритет:** must · **Оценка трудоёмкости:** 12 часов

**Acceptance Criteria:**
- Система формирует ровно 3 инициативы, ранжированные по ожидаемому экономическому эффекту
- По каждой инициативе: описание действия, ожидаемое снижение потерь (%), расчёт ROI, срок окупаемости
- Итоговый отчёт с инициативами готов за ≤5 минут с момента загрузки файла

## 3. Definition of Done (DoD) для AI-функции

### Функциональная полнота

- [ ] Пользователь загружает CSV/Excel-файл стандартной выгрузки 1С без ручной предобработки — файл принимается и обрабатывается корректно
- [ ] Структура потерь классифицирована по ≥4 категориям (порча, кража, ошибки учёта, прочее) с суммами и долями в %
- [ ] Выявлено ≥3 аномалии (топ по сумме или отклонению от среднего) с указанием магазина / категории / периода
- [ ] Сформированы ровно 3 инициативы: каждая содержит название, описание действия, ожидаемый эффект (%), ROI и срок окупаемости
- [ ] Итоговый отчёт содержит дисклеймер согласно AI Policy п. 4.5

### Качество AI-компонента

- [ ] Точность классификации типов потерь **≥ 80 %** на 20 вручную размеченных тест-файлах (≥5 различных конфигураций 1С)
- [ ] Все 3 инициативы содержат конкретные числовые показатели (не общие формулировки)
- [ ] Релевантность инициатив подтверждена доменным экспертом: ≥2 из 3 признаны применимыми на реальных данных ритейла

### Производительность

- [ ] Latency p95 **≤ 5 минут** от загрузки файла до отображения полного отчёта (файл до 10 000 строк)
- [ ] Приложение обрабатывает файл размером до 50 МБ без краша и потери данных

### Устойчивость и соответствие AI Policy

- [ ] При файле <50 строк или отсутствии обязательных колонок система возвращает понятное сообщение об ошибке (не инициативы)
- [ ] Тест на prompt injection (T-6): ячейка файла с текстом «Ignore previous instructions» не меняет поведение системы
- [ ] JSON-ответ Claude проходит валидацию схемы по AI Policy п. 4.3 на всех 5 happy-path тест-файлах

### Воспроизводимость и готовность к демо

- [ ] README содержит инструкцию запуска ≤2 команды; любой участник команды воспроизводит прототип с нуля
- [ ] Промпты версионированы в `/ai/prompts/` (файлы `analyze_v1.md`, `initiatives_v1.md`); конфиги в `.env`
- [ ] Подготовлено ≥5 тест-сценариев: 2 happy path (разные форматы 1С), 1 edge case (нетипичные категории), 1 негатив (некорректный файл), 1 проверка AI Policy guard
- [ ] Демо прогнано end-to-end на синтетических данных; скриншоты / запись прикреплены к PR

## 4. AI Policy

### 4.1. Границы применения AI

**Что AI делает:** классифицирует строки списаний по типам потерь (порча / кража / ошибки учёта / прочее); выявляет паттерны и аномалии в разрезе товаров, магазинов, периодов; генерирует 3 приоритизированные инициативы с расчётом ROI и сроком окупаемости.

**Что AI НЕ делает:** не ставит диагнозы конкретным сотрудникам и не называет виновных; не принимает управленческих решений; не гарантирует точность финансовых прогнозов (расчёты являются оценочными); не обрабатывает данные за пределами загруженного файла.

### 4.2. Источники данных

**Используются:** загруженный пользователем CSV/Excel-файл (данные о списаниях из 1С) только в рамках текущей сессии; не сохраняется после завершения сессии.

**Запрещены в контексте:** данные других компаний; корпоративная переписка; конфиденциальная финансовая отчётность за пределами загруженного файла.

**PII / чувствительные данные:** если в файле присутствуют ФИО сотрудников — система их не использует для анализа и не отображает в отчёте. Файл не логируется и не передаётся третьим сторонам.

### 4.3. Формат ответа

**Структура:** JSON-объект + markdown-отчёт для рендеринга в UI.

**Обязательные поля:** `loss_structure` (категории, суммы, доли), `top_anomalies` (≥3 аномалии), `initiatives` (ровно 3: название, описание, ожидаемый эффект %, ROI, срок окупаемости), `disclaimer`.

**Ограничения по длине:** итоговый отчёт ≤2 000 токенов; описание каждой инициативы ≤150 слов; весь JSON умещается в контекст модели.

### 4.4. Поведение при «не знаю» / низкой уверенности

Если данных в файле недостаточно (менее 50 строк, отсутствуют обязательные колонки или формат не распознан как выгрузка 1С) — система явно сообщает: «Данных недостаточно для полного анализа» и указывает, каких полей не хватает. Инициативы не генерируются при низкой уверенности в данных.

### 4.5. Эскалация / отказ / дисклеймеры

Итоговый отчёт сопровождается дисклеймером: «Анализ носит рекомендательный характер. ROI-расчёты являются оценочными и требуют верификации на реальных данных компании.» Система не отвечает на вопросы за пределами анализа загруженного файла.

### 4.6. Защита от prompt injection и злоупотреблений

Загружаемый файл обрабатывается строго как табличные данные — содержимое ячеек не интерпретируется как инструкции для модели. Пользовательский файл изолирован от системного промпта разделителем ролей. При обнаружении нетипичного содержимого (не похожего на данные 1С) — система возвращает ошибку формата, не изменяя поведения.

## 5. Архитектура решения

### 5.1. Общая схема

**Компоненты:**
- **Фронт:** Streamlit — форма загрузки файла, отображение структурированного отчёта
- **Бэк / API:** Python, FastAPI — парсинг и валидация файла, оркестрация AI-пайплайна
- **AI-компонент:** Claude API (Anthropic) — классификация потерь, выявление аномалий, генерация инициатив с ROI
- **Хранилище / БД / Vector DB:** файл хранится только в памяти сессии (не сохраняется); промпты — в `/ai/prompts/`
- **Внешние сервисы:** Anthropic Claude API (claude-sonnet-4-6); TODO: рассмотреть GigaChat как альтернативу

### 5.2. AI-компонент

**Какую задачу решает:** анализ табличных данных о списаниях из 1С → структурированный отчёт с диагностикой структуры потерь и 3 приоритизированными инициативами с ROI.

**Подход:** prompt + data-in-context — агрегированные данные из файла (топ-категории, аномалии, суммы) передаются в системный промпт.

**Модель:** Claude Sonnet (Anthropic API) — TODO: уточнить после сравнения качества с GigaChat в день 1.

**Почему такой выбор:** Claude демонстрирует высокое качество анализа табличных данных и структурированного JSON-вывода; обеспечивает latency ≤5 мин для файлов до 10 000 строк без дополнительного fine-tuning.

### 5.3. Поток данных

1. Пользователь загружает CSV/Excel через веб-интерфейс Streamlit → `POST /api/analyze`
2. FastAPI парсит файл (pandas), валидирует наличие обязательных колонок (дата, SKU, магазин, тип списания, сумма)
3. Данные агрегируются по категориям и магазинам; вычисляются топ-аномалии; результат конвертируется в компактный текст
4. Агрегированный текст подставляется в промпт → Claude API: классификация + выявление паттернов + генерация 3 инициатив с ROI
5. JSON-ответ Claude парсится, Streamlit рендерит структурированный отчёт: диагностика + инициативы + дисклеймер

| User Story / требование | Компонент архитектуры | Технология / инструмент | Статус |
|---|---|---|---|

| US-2 (инициативы + ROI) | Промпт генерации инициатив | Claude API + `prompts/initiatives_v1.md` | mock (ROI-коэффициенты фиксированы) |

## 6. Ограничения и риски MVP

### 6.1. Out-of-scope (что НЕ войдёт в 3-дневный MVP)

- Прямая интеграция с 1С через API (только ручная выгрузка файлом CSV/Excel)
- Авторизация, история сессий, личный кабинет, сравнение динамики по периодам
- Поддержка форматов, отличных от стандартных выгрузок 1С (кастомные конфигурации)

### 6.2. Заглушки и mock-данные

- ROI-коэффициенты по категориям потерь — фиксированные значения в промпте (не на основе реальной отраслевой статистики); используются как ориентировочные для MVP
- Синтетические тест-данные: 5 CSV-файлов сгенерированы командой (не из реальной 1С) — достаточно для демонстрации корректности пайплайна на защите

### 6.3. Топ-3 риска

| Риск | Категория | Вероятность | Влияние | Mitigation |
|---|---|---|---|---|
| Форматы выгрузки из 1С сильно варьируются между конфигурациями | тех | Высокая | Высокое | Подготовить 5 тест-файлов разных форматов 1С; нормализация колонок в парсере |
| Claude не классифицирует специфичные категории 1С-списаний с нужной точностью | AI | Средняя | Высокое | Ручная разметка 20 тест-файлов перед демо; итерация промпта по результатам |
| Файл >10 000 строк превышает контекст LLM или даёт latency >5 мин | тех | Средняя | Среднее | Агрегировать данные до передачи в промпт: топ-категории, суммы, аномалии — не сырые строки |

### 6.4. Допущения

- Пользователь умеет выгружать данные из 1С в CSV/Excel — это стандартная операция для целевой аудитории
- Файл содержит распознаваемые колонки: дата, SKU/наименование товара, код или название магазина, тип списания, сумма списания
